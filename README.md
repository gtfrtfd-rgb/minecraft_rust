# Minecraft Rust

[![Build](https://github.com/gtfrtfd-rgb/minecraft_rust/actions/workflows/build.yml/badge.svg)](https://github.com/gtfrtfd-rgb/minecraft_rust/actions/workflows/build.yml)

Воксельная игра в стиле Minecraft, написанная на **Rust** с использованием движка **Bevy 0.20**.

> 🤖 **Весь код этого проекта полностью написан искусственным интеллектом** — от генерации мира до ИИ мобов. Никакой ручной работы программиста.

---

## ✨ Возможности

### 🌍 Мир
- **Бесконечный мир** — чанки генерируются и выгружаются на лету по мере движения игрока
- **Chunk streaming** — прогрузка/выгрузка с приоритетом по полю зрения
- **Асинхронная генерация чанков** — через `AsyncComputeTaskPool`, не блокирует основной поток
- **Асинхронное построение мешей** — снимок чанка с halo-соседями уходит в фоновый поток
- **Кэш Perlin** — 4 шумовых генератора создаются один раз на seed, а не на каждый чанк
- **Процедурная генерация** — Perlin-шум, биомы, рельеф, деревья
- **5 биомов** — равнины, лес, пустыня, снег, горы
- **2 типа деревьев** — дуб (раскидистый) и сосна (ёлка)
- **Рост травы** — блоки земли рядом с травой постепенно зарастают
- **Меню миров** — создание, выбор, удаление, переименование миров

### ☁️ Небо
- **Солнце** — яркий белый квад в небе, всегда висит в одном направлении от игрока
- **Облака** — процедурная текстура 256×256 на подразделённой плоскости 100000×100000
- **Медленный дрейф** — облака плывут по ветру
- **Не дёргаются при повороте камеры** — linear-фильтрация + подразделённая сетка
- **Привязаны к миру** — не «прилипают» к игроку при ходьбе

### 🎮 Геймплей
- **DDA-рейкаст** — точное определение блока под прицелом
- **Ломание блоков с удержанием** — контур блока плавно меняет цвет (чёрный → оранжевый → красный)
- **Установка блоков** — ПКМ, мгновенно
- **9 блоков в хотбаре** — трава, земля, камень, булыжник, песок, дерево, листва, доски, кирпич
- **Физика игрока** — гравитация, прыжки, бег, приседание, полёт
- **Bunny-hop** — зажми Space для автопрыжков
- **Coyote time + jump buffer** — отзывчивое управление
- **Настройка управления** — все клавиши можно переназначить, с предупреждением о конфликтах

### 🐷 Мобы
- **4 типа** — свинья, овца, корова, курица
- **Единый атлас 128×64** — все мобы на одной текстуре, один материал на всех
- **Процедурные меши** — тело, голова, глаза, пятачок, рога, гребень, клюв
- **Двухслойные глаза** — тёмный зрачок + светлая окантовка (белок)
- **Белые пятна на корпусе** — у коровы, асимметрично
- **AI на 4 состояния** — Idle / Wander / Alert / Flee
- **Реагируют на игрока** — замечают в радиусе 6–9 блоков, отворачиваются, убегают после удара
- **Анимация ног** при ходьбе
- **Обход препятствий** — прыгают через блоки, разворачиваются у стен
- **Spatial hash** для расталкивания — O(N) вместо O(N²)
- **Спавн и деспавн в стиле Minecraft**:
  - Циклический спавн раз в 4 секунды в радиусе 24–128 блоков
  - Стайный спавн — 2–4 моба одного типа рядом
  - Лимит 30 мобов в радиусе 128 блоков
  - Мгновенный деспавн дальше 128 блоков
  - Случайный деспавн через 30 секунд без игрока рядом

### 🔊 Звуки
Всё **процедурное** — WAV-файлы генерируются в память при запуске, никаких внешних ассетов.
- **Разные звуки ломания по материалам** — камень «крак», дерево «ток», стекло «дзинь», кирпич «клац», трава «пуф»
- **Разные звуки установки по материалам** — глухой «тук» для земли, звонкий «клац» для камня, полый «ток» для дерева, «дзынь» для стекла, сухой «клац» для кирпича
- **Случайный питч 0.8–1.0** при ломании и установке — как в MC
- **Разные звуки шагов по материалам** — цок по камню, тук по дереву, шуршание по песку, глухой шорох по траве
- **4 варианта каждого звука шага** — не звучат однообразно
- **Непрерывный звук при движении** — шаги накладываются друг на друга
- **Отдельный звук в присяде** — тише, питч выше, шаги реже
- **Звук приземления после прыжка** — ниже тоном, зависит от высоты падения
- **Звук приземления в bunny-hop** — срабатывает даже когда следующий прыжок стартует в тот же кадр
- **Звук удара по мобу** — «шлёпок» с разбросом питча

### 🎨 Интерфейс
- **Главное меню** — SINGLEPLAYER / SETTINGS / EXIT
- **Меню миров** — список, создание, удаление, переименование, информация о сиде и правках
- **Меню паузы** — по Esc, с кнопкой настроек
- **Меню настроек** — громкость, чувствительность мыши, render distance, FPS-лимит, VSync, разрешение
- **Экран управления** — переназначение всех клавиш + предупреждение о конфликтах
- **Хотбар** — 9 слотов с номерами
- **HUD** — координаты, FPS
- **Прицел** — белый крестик в центре
- **Подсветка блока под прицелом** — чёрный контур, меняется на оранжево-красный при ломании

| Клавиша | Действие |

## ⚙️ Настройки

Все настройки сохраняются в `settings.json` в системной папке данных и восстанавливаются при следующем запуске.

| Настройка | Диапазон | По умолчанию |
|---|---|---|
| Master Volume | 0 – 100% | 80% |
| Mouse Sensitivity | 0.0005 – 0.0060 | 0.0022 |
| Render Distance | 4 – 32 чанка | 12 |
| FPS Limit | 30 / 60 / 90 / 120 / 144 / 165 / 180 / 240 | 60 |
| VSync | On / Off | On |
| Resolution | 720p / 900p / 1080p / 1440p / 4K | 1280×720 |

**Про разрешение.** Список доступных разрешений ограничен физическим разрешением монитора. Если выбрать нативное разрешение монитора, игра автоматически разворачивается в **borderless fullscreen**.

**Про FPS Limit и VSync.** Когда VSync включён, ограничение FPS игнорируется — VSync сам синхронизирует кадры с монитором. Чтобы FPS Limit работал, выключи VSync.

## 🛠 Установка (для разработки)

### Требования

- **Rust 1.85+** — установить с [rustup.rs](https://rustup.rs)

**Платформо-специфичные:**

- **Windows** — **MSVC Build Tools**: [visualstudio.microsoft.com](https://visualstudio.microsoft.com)
- **Linux** — требует системные библиотеки **ALSA** (аудио), **Wayland**, **X11** и **Vulkan**. На Ubuntu/Debian:

      sudo apt-get install -y \
        pkg-config libasound2-dev libudev-dev \
        libwayland-dev libxkbcommon-dev \
        libx11-dev libxcursor-dev libxrandr-dev \
        libxi-dev libxinerama-dev \
        libvulkan-dev libssl-dev

  На Fedora/Arch — аналогичные пакеты через `dnf`/`pacman`.
- **macOS** — **собирается из коробки**, дополнительных зависимостей не требуется.

### Сборка и запуск

    git clone https://github.com/gtfrtfd-rgb/minecraft_rust.git
    cd minecraft_rust
    cargo run --release

Первая сборка — 5–15 минут. Последующие — 30 сек – 2 мин.

### CI

GitHub Actions:

- **Windows** — полная сборка `--release`, публикует `.zip` как artifact.
- **Linux** — `cargo check --all-targets` с полным набором Bevy-зависимостей (ALSA, Wayland, X11, Vulkan).
- **macOS** — `cargo check --all-targets`.

Linux и macOS job'ы не публикуют бинарники — только проверяют компиляцию.

## 💾 Сохранения

**Путь к сохранениям** (системная папка данных):

- **Windows**: `%APPDATA%\minecraft_rust\` (типично `C:\Users\<User>\AppData\Roaming\minecraft_rust\`)
- **macOS**: `~/Library/Application Support/minecraft_rust/`
- **Linux**: `~/.local/share/minecraft_rust/`

Структура папки:

    minecraft_rust/
    ├── saves/
    │   └── settings.json         # Настройки игры и раскладка клавиш
    └── worlds/
        ├── New_World.json         # Мир: сид, позиция игрока, правки блоков, имя
        ├── Default.json
        └── ...

**Мир = один JSON-файл.** Внутри: сид, позиция игрока, права всех изменённых блоков, имя мира. Благодаря chunk streaming целый мир не хранится на диске — сохраняются только сид и то, что игрок изменил.

**Автосохранение** — каждые 30 секунд и при выходе из игры.

**Старые сейвы** (рядом с `.exe`) при первом запуске автоматически мигрируют в новое место.

## 🔊 Как устроен звук

Никаких внешних `.wav` — все звуки синтезируются при запуске.

1. **На Startup** `GameAudioPlugin` генерирует PCM-сэмплы для 5 материалов ломания, 5 материалов установки, 4 материалов шагов (по 4 варианта каждого), удара по мобу.
2. Сэмплы кодируются в WAV-байты через `hound` и заворачиваются в `AudioSource` **прямо в памяти**.
3. Хендлы лежат в `SoundHandles`, а системы `breaking.rs` и `footsteps.rs` спавнят `AudioPlayer` с нужным питчем и громкостью.

Синтез — шумовой LCG + синусоидальные моды с разными огибающими. Разный характер материалов достигается фильтрацией (low-pass / high-pass) и набором резонансных частот.

## ☁️ Как устроено небо

`world/sky.rs` — три системы:

1. **`sun_follow_player`** — солнце всегда висит в направлении `(0.5, 1.0, 0.35)` от игрока на расстоянии 1500. При беге визуально не двигается (расстояние много больше смещения).
2. **`update_clouds`** — двигает плоскость облаков за игроком по XZ, компенсирует это движение через UV-сдвиг (чтобы облака оставались на месте в мире), плюс добавляет медленный дрейф. Работает только в `AppState::InGame`.
3. **`drift_clouds`** (часть `update_clouds`) — накапливает `uv_offset` в `Local<Vec2>` и wrap'ает его по 1.0, чтобы f32 не терял точность при долгой игре.

**Текстура облаков** — 256×256, многооктавный value-noise (7 октав, базовая частота 6, жёсткий порог по alpha). Nearest-фильтр на магнификации, Linear на минификации + мипмапы — это убирает дёрганье при повороте камеры.

**Плоскость** — подразделённая сетка 16×16 (289 вершин). В отличие от `Plane3d` (2 треугольника), точная UV-интерполяция на больших размерах.

**Солнце** — квад 250×250 с `emissive = 50.0`. Без `unlit`, чтобы HDR-pipeline пропустил яркость через tone mapping и выжег в чистый белый.

## 🧱 Как устроен chunk streaming

- Мир хранится в `HashMap<IVec2, ChunkData>` — только загруженные чанки.
- Правки игрока хранятся отдельно (`edits`) и накладываются поверх сгенерированного чанка при загрузке.
- Каждый кадр `stream_chunks` работает в шесть фаз:
  1. **Первый кадр в мире** — синхронная генерация 3×3 чанков, чтобы игрок не упал в пустоту.
  2. **Поллинг готовых задач генерации** — вставляет чанки в мир.
  3. **Поллинг готовых задач меша** — спавнит entity с готовым mesh.
  4. **Планирование задач меша** — до 8 задач/кадр, до 16 в полёте.
  5. **Выгрузка мешей** за пределами `render_distance`.
  6. **Выгрузка чанков из памяти** за `render_distance + 4` и планирование новых задач генерации.
- **Приоритет по полю зрения** — передние чанки грузятся в 3 раза раньше задних.
- **Perlin кэш** — 4 генератора на seed, пересоздаются только при смене мира.

## 🌱 Как растёт трава

`world/grass.rs` — раз в 0.4 секунды делает 12 попыток распространения:

- Выбирается случайный загруженный чанк в радиусе 3 от игрока.
- Случайный столбец в этом чанке.
- Сверху вниз ищется блок **Dirt**, над которым нет solid-блока.
- Если у него есть **Grass** в 6-соседних клетках — Dirt превращается в Grass.

Рост идёт только в 96 блоках от игрока.

## ⚡ Производительность

- **Async-генерация чанков** — фоновые worker-потоки, основной поток почти не нагружен.
- **Async-меши** — снимок чанка с halo-соседями уходит в фоновый поток.
- **Прямой доступ к блокам чанка** — `get_local_fast` без HashMap/div/rem в горячем цикле.
- **`Vec::with_capacity`** — нет переаллокаций при сборке мешей.
- **Spatial hash для мобов** — O(N) вместо O(N²) при расталкивании.
- **Кэш Perlin** — 4 генератора на seed, не на чанк.
- **Единый атлас мобов** — один материал и один batch вместо четырёх.
